# SIMULATOR SMOKE TESTS — NOT PHYSICAL HARDWARE DATA

> **CRITICAL:** All CSV files in this directory are **software simulation outputs**.
> They were generated by a Python script with a hard-coded reflectance baseline
> plus injected Gaussian noise. They do **NOT** represent measurements from a
> physical AMS AS7265x sensor.

---

## Why These Files Exist

These files were created during the software bring-up phase to verify that:
1. The data pipeline (CSV → normalisation → model) runs without errors.
2. The calibration math (dark/white reference formula) produces plausible values.
3. The repeatability audit harness loops and writes output correctly.

They are **smoke tests**, not validation data.

---

## What Is Wrong With Treating Them as Hardware Data

| Claim that was made | Reality |
|---|---|
| "CV < 0.5%, PASS" repeatability | The injected noise *was* 0.5%. The "PASS" is circular. |
| "Four illumination modes give different readings" | The modes are simulated by scalar weighting of the same base curve — no real LED physics. |
| "Untreated apples read 1.000 reflectance" | Hard-coded `base_curve` returning ~1.0 on a PTFE target. |
| `is_simulation=False` in the file header | The driver silently fell back to simulation when `smbus2` was absent. |

---

## Correct Interpretation

- These files prove the **software pipeline runs correctly**.
- They say **nothing** about real sensor noise, LED thermal drift, or fruit reflectance.
- Real hardware repeatability data will be collected when the physical AS7265x triad arrives.

Real hardware measurements will be stored in:
```

```

```
PHYSICAL__<YYYYMMDD>__<target>__<n_repeats>__<operator>.csv
```
and a mandatory header field: `data_provenance: "physical_as7265x_hardware"`.
