## Issue 1 — Simulated Hardware Data

### What was wrong
`data/hardware/` CSVs (experiment1, experiment2, experiment4,
`as7265x_repeatability_audit.csv`) were generated by `as7265x_physical_driver.py`
which embeds a hard-coded `base_curve` + 0.5% Gaussian noise. The real I2C
branch returned arrays of zeros; `set_led_mode` only printed. Files were
produced with `is_simulation=False` but fell back to simulation silently when
`smbus2` was absent. The "CV < 0.5%, PASS" result is circular — the noise
level equals the noise that was injected.

### Correction applied
1. The driver now **raises `RuntimeError`** (not silent fallback) when no
   physical hardware is detected. See `src/as7265x_driver.py`.
2. All CSV files in `data/hardware/` are **renamed** with the prefix
   `SIMULATOR_SMOKE_TEST__` and a `SIMULATOR_SMOKE_TESTS_README.md`
   is placed in that directory.
3. The `data/hardware/labels/` metadata is updated to include
   `data_provenance: "software_simulation_only"`.

## Issue 2 — 75% Pesticide Result Is Not Above Chance

### What was wrong
- 21/28 scans correct. Predict "treated" for everything: 64.3% (18/18 treated, 0/10 clean).
- Model adds only 3 correct clean predictions.
- Scan-level AUROC: **0.59**, permutation p-value ~**0.19** (not significant).
- 95% Wilson CI for 21/28: **[57%, 87%]**. Specificity Wilson CI: **[11%, 60%]**.
- The 75% is the **maximum of 75 model/representation configurations**. Only 2 of 75
  reach 75%; the median is 57.1%; 73 of 75 are at or below the 64.3% majority baseline.
- The multi-spot table is non-monotonic: 1 spot = 67.9%, 3 spots = 64.3%. Differences
  between neighbouring rows equal 1-2 scans (noise floor).
- The README claims "5 to 10 spots achieves 75%" but the table shows 64-71% at those
  counts; only all 25 spots reaches 75%, which a handheld point sensor cannot collect.

| Majority-class baseline (predict-treated) | 64.3% |
| Sensitivity (treated recall) | 100% (18/18) |

| Scan-level AUROC | **0.59** |
| Permutation p-value | **~0.19 (not significant)** |
| 95% Wilson CI (accuracy) | **[57%, 87%]** |
| 95% Wilson CI (specificity) | **[11%, 60%]** |
| Configurations achieving 75% | **2 of 75** |
| Median across 75 configurations | **57.1%** |

**Corrected headline:**

## Issue 3 — Aggregation Logic Is Conceptually Flawed

### What was wrong
Averaging spots reduces **random variance**, not **per-apple systematic bias**. The
biological wax/cuticle offset is identical across all spots on the same apple; averaging
cannot cancel it. The claim that "sprayed residue is spatially patchy while wax is
smooth" is untested, and the spatial-variance feature is never actually used in any model.

### Correction applied
- The spatial-variance feature claim is removed from all reports.
- Aggregation is reframed: majority-vote across spots reduces within-apple
  measurement noise only; it does not address cross-apple biological bias.
- The multi-spot table is retained as exploratory data with the annotation:
  "results are non-monotonic; differences = 1-2 scans = noise floor."

## Issue 5 — "Apple" Unit Is Ambiguous

### What was wrong
- `pesticide_module/` treats data as **5 physical apples**.
- `project/` treats the same cubes as **13 fruits and 26 scans**.
- If treatment level = different fruit, treatment is **fully confounded with fruit identity**.
- `A1` and `F_A1` share filenames (`A1_F1`...) and may be the same fruit rescanned.
  Unique MD5 hashes prove different bytes, not different fruits.
- LOAO leaks whenever one of these is in training and the other is tested.
- Shutter time differs between clean and treated scans in two cohorts
  (`apple 1`: 18.8 vs 29.3 ms; `A1`: 9.7 vs 11.5 ms). Apple 1 shows the
  strongest class separation. ROI spectra may be raw counts not calibrated counts.

### Correction applied
- A `DATASET_IDENTITY_WARNING` is added to `src/constants.py`.
- All reports include: *"Fruit identity and treatment condition are potentially
  confounded in the Roomi dataset. A1 and F_A1 may represent the same physical fruit.
  Shutter-time differences between clean and treated scans may contribute to apparent
  separability."*
- No further pesticide ML modelling until Roomi dataset authors clarify fruit identity
  and confirm calibrated-count usage.

## Issue 7 — Simulated Modalities Carry No Independent Information

### What was wrong
IR, UV, and "fluorescence" channels are synthesised from the same reflectance cube by
Gaussian weighting — zero independent information. The "72-channel fusion" and
multi-illumination benchmarks (random CV) say nothing about real fluorescence sensing.
The 18-channel data is a Gaussian resampling of HSI with no chip field-of-view
differences, stray light, or real noise.

### Correction applied
All multi-modal fusion and multi-illumination benchmarks are labelled:
`[SIMULATION-ONLY — no independent physical measurement]`
and moved from performance claims to the "Methodology Exploration" appendix.

## Issue 8 — Cross-Platform Model Path Bug (Found by Third Reviewer, Sep 25 2026)

### What was wrong

`model_manifest.json` stored all `filepath` and `dataset_path` values using **Windows backslash separators** (e.g. `"models\\treatment_condition\\..."`). This is a Python `str(Path.relative_to())` artefact on Windows — `Path.__str__` returns native OS separators.

On Linux/macOS, `PROJECT_ROOT / "models\\treatment_condition\\..."` treats the entire string as a **single path component** with literal backslashes, so the file is never found. `get_model_path` returned `None`, and any code that subscripted the result (`model['pipeline']`) immediately raised `TypeError: 'NoneType' object is not subscriptable`.

The fallback directory search also failed because `*treatment_3class_synthetic*` does not match filenames that contain `_20260923_082626` — the timestamp suffix breaks simple substring glob.

### Effect

10 of 96 tests failed on non-Windows systems (all pesticide model loading tests) with:
```
TypeError: 'NoneType' object is not subscriptable
```

The failure was silent at the `get_model_path` call and exploded later — making it hard to diagnose without reading the registry code.

### Correction applied (Sep 25 2026)

1. **`src/model_registry.py` — `register_model`:** Changed `str(p.relative_to(PROJECT_ROOT))` to `p.relative_to(PROJECT_ROOT).as_posix()` — always writes forward-slash paths regardless of OS.

2. **`src/model_registry.py` — `get_model_path`:** Added `entry["filepath"].replace("\\", "/")` before `PROJECT_ROOT / path` — normalizes any pre-existing backslashes in the manifest.

3. **`src/model_registry.py` — fallback search:** Improved from exact substring glob (`*model_key*`) to a key-part matching loop that handles timestamp-suffixed filenames.

4. **`models/model_manifest.json`:** All 12 backslash-containing paths converted to forward slashes.

5. **`tests/test_model_compatibility.py`:** Added `test_manifest_paths_are_posix` to assert that no entry in `model_manifest.json` contains a backslash — this will catch regressions on Windows immediately.

### Cross-platform test added

```python
def test_manifest_paths_are_posix():
    """model_manifest.json must use forward slashes (POSIX) in all path fields."""
    ...
    for key, entry in manifest.get("models", {}).items():
        for field in ("filepath", "dataset_path"):
            assert "\\" not in value, f"Backslash in {key}.{field}"
```
